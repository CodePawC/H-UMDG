# 代码风格与命名约定

> 工作区通用约定，适用于 H-UMDG 和 H-MELC 两个独立项目。
> 目的是降低跨项目阅读代码时的思维切换成本，不在两个项目中各自发明轮子。

---

## 1. 命名约定

### 1.1 Python

| 要素 | 约定 | 示例 |
|------|------|------|
| 包/模块 | `snake_case` | `supplier_portal`, `master_data_source` |
| 类 | `PascalCase` | `class Asset(Base)`, `class JwtClaims` |
| 函数/方法 | `snake_case` | `def ensure_minio_bucket()` |
| 变量 | `snake_case` | `db_session`, `access_token` |
| 常量（模块级） | `UPPER_SNAKE_CASE` | `RBAC_ASSET_READ`, `_PG_REQUIRED` |
| 私有关联（前缀） | `_` 开头 | `_ensure_pg_dashboard()`, `_legacy_crypt()` |
| 类型变量 | `PascalCase` | `DbSession = Depends(...)` |

### 1.2 TypeScript / React

| 要素 | 约定 | 示例 |
|------|------|------|
| 组件文件 | `PascalCase.tsx` | `AssetCreatePage.tsx` |
| 组件函数 | `PascalCase` | `function AssetDetailPage()` |
| 工具/库模块 | `camelCase.ts` | `appMeta.ts`, `authProfileStorage.ts` |
| 变量/函数 | `camelCase` | `const handleLogin = () => ...` |
| 类型/接口 | `PascalCase` | `type MasterDataMode = 'local' | 'service' | 'hybrid'` |
| API 函数 | `camelCase` | `fetchAssetDetail()`, `loginUser()` |

### 1.3 数据库

| 要素 | 约定 | 示例 |
|------|------|------|
| schema 名 | `snake_case`, 单数 | `identity`, `asset`, `supplier` |
| 表名 | `snake_case`, 单数 | `app_user`, `process_instance` |
| 列名 | `snake_case` | `asset_code`, `main_status`, `created_at` |
| 主键 | `id` | `id: Mapped[uuid.UUID]` |
| 外键 | `{目标表}_id` | `organization_id`, `user_id` |
| 时间列 | `{动词}_at` | `created_at`, `updated_at`, `reviewed_at` |
| 状态列 | `{domain}_status` | `review_status`, `archive_status`, `main_status` |
| 启用状态 | `is_active` (bool) | 统一使用 `Boolean` 类型 |

## 2. Python 通用模式

### 2.1 ORM 基类

两个项目统一使用 SQLAlchemy 2.0 `DeclarativeBase`：

```python
from sqlalchemy.orm import DeclarativeBase

class Base(DeclarativeBase):
    pass
```

### 2.2 模型字段顺序

按以下顺序声明：

```python
class Asset(Base):
    __tablename__ = "asset"
    __table_args__ = {"schema": "asset"}

    # 1. 主键
    id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    # 2. 业务标识（编码/名称）
    asset_code: Mapped[str] = mapped_column(String(64), unique=True, index=True)
    asset_name: Mapped[str] = mapped_column(String(256))
    # 3. 外键
    organization_id: Mapped[uuid.UUID | None] = mapped_column(UUID(as_uuid=True), ForeignKey("org.organization.id"))
    # 4. 状态
    main_status: Mapped[str] = mapped_column(String(64), nullable=False, default="ACTIVE")
    is_active: Mapped[bool] = mapped_column(Boolean, nullable=False, default=True)
    # 5. 时间戳
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    updated_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), onupdate=func.now())
```

### 2.3 状态枚举

状态字段统一使用 **大写字符串**，不做整数或布尔状态机：

```
ACTIVE / INACTIVE          # 启停用
PENDING / APPROVED / REJECTED    # 审批
DRAFT / SUBMITTED / CLOSED       # 单据
draft / active / archived         # ❌ 不混用大小写
```

新旧项目都遵守，已在代码中的逐步迁移，新增代码一律使用大写。

### 2.4 API 响应格式

**H-MELC** 统一使用信封格式：
```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

辅助函数：`app.core.responses.envelope_ok()`

**H-UMDG** 当前不强制统一信封，但标准主数据接口（`/api/v1/master-data/*`）建议返回一致结构以便 H-MELC 适配器消费。

### 2.5 路由文件 docstring

每个 `router.py` 文件顶部写清楚：

```python
"""模块名 + 简要职责。

对齐 docs/... 的章节号。
"""
```

### 2.6 错误处理

- 使用 `HTTPException` 抛出 HTTP 错误
- 非 PostgreSQL 环境返回 `503` + 引导信息
- `SQLAlchemyError` 统一捕获并转为 `503`

## 3. TypeScript / React 通用模式

### 3.1 API 请求函数

每个业务模块对应一个 `src/api/{module}.ts` 文件：

```typescript
// src/api/assets.ts
export async function fetchAssets(params: AssetQueryParams): Promise<PaginatedResult<Asset>> {
  return api.get('/api/v1/assets', { params })
}
```

### 3.2 页面组件结构

```typescript
// src/pages/AssetCreatePage.tsx
import { useState } from 'react'
// <= 标准库导入
import { Button, Form } from 'antd'
// <= 第三方库导入
import { fetchAssets } from '@/api/assets'
import { AssetForm } from '@/components/AssetForm'
// <= 本地导入

function AssetCreatePage() {
  // 状态 + 副作用
  // 事件处理
  // 渲染
}
```

### 3.3 状态管理

- 使用 `zustand`（H-MELC）或 React 本地状态
- 不引入 Redux
- 全局状态（如认证）放 `src/stores/`，业务状态就近放在组件内

## 5. 测试约定

### 5.1 文件命名

```
test_{模块}_{场景}.py
# 示例：
test_asset_postgres_integration.py     # PostgreSQL 集成测试
test_master_data_config_contract.py     # 契约测试
test_spec_parse.py                      # 单元测试
test_api_v1.py                          # API 测试
```

### 5.2 测试函数命名

```python
def test_{场景}():
def test_{功能}_{条件}_{预期结果}():
```

示例：
```python
def test_master_data_default_mode_is_hybrid_for_humdg_closed_loop():
def test_local_mode_does_not_force_external_provider():
```

PostgreSQL 依赖的测试通过 fixture 自动跳过：

```python

# 测试用例调用 skip_without_identity_jwt(pg_admin_headers)
```

## 6. Git 提交

| 前缀 | 用途 |
|------|------|
| `feat:` | 新功能 |
| `fix:` | 缺陷修复 |
| `refactor:` | 重构（不改变外部行为） |
| `test:` | 测试新增或修正 |
| `docs:` | 文档变更 |
| `chore:` | 构建、CI、配置等 |
| `style:` | 代码风格（不影响逻辑） |

示例：
```
feat: 资产建档页支持标准通用名称选择器
fix: 维修工单分页在无数据时返回空数组而非 null
docs: 更新 H-MELC 本地联调端口说明
```

## 7. H-UMDG 与 H-MELC 特定约定

### H-UMDG 特有

- 后端模型集中在 `app/models/tables.py`（非按模块分散）
- API 路由在 `app/api/routes/`（按资源，非按模块）
- 业务逻辑在 `app/services/`（按职能）
- 构建后端：`hatchling`

### H-MELC 特有

- 后端按领域模块分散：`app/modules/{domain}/{model,router,schema,service}.py`
- 管理前端在 `frontend-admin/src/`
- 移动前端在 `frontend-mobile/src/`
- 构建后端：`setuptools`

## 8. 跨系统共享规范

跨项目字段统一使用以下命名：

| 概念 | 统一字段名 | 说明 |
|------|-----------|------|
| 来源标识 | `source` | `local`, `H-UMDG`, `cache` |
| 来源 ID | `{entity}_id` | 主数据平台的稳定 ID |
| 来源编码 | `{entity}_code` | 业务交换使用的编码 |
| 名称快照 | `{entity}_name_snapshot` | 业务发生时点的名称 |
| 版本号 | `{entity}_version` | 标准版本标识 |
| 启用/停用 | `is_active` | boolean，`true` = 启用 |
| 主数据模式 | `MASTER_DATA_MODE` | `local`, `service`, `hybrid` |
